# Архитектура и перенос атласа на другую территорию

Этот документ описывает **текущую реализацию**, а не абстрактный фреймворк. Проект представляет собой статический сайт без API и базы данных при просмотре. Браузер читает подготовленные GeoJSON/JSON/CSV по HTTP. Python-скрипты создавали часть этих данных до публикации и не запускаются браузером.

## Как читать код

| Файл | Ответственность | Что важно при изменении |
| --- | --- | --- |
| `index.html` | Структура панелей, элементов управления и порядок подключения скриптов | Порядок `atlas-geometry.js` → `app.js` → `selection-sketch.js` → `map-runtime.js` → `timeline-axis.js` обязателен. Leaflet должен загрузиться до них. |
| `style.css` | Оформление интерфейса, слоёв Leaflet и экспорта | Стили с историческими суффиксами `v*` остаются действующими, переименовывать их отдельно от JS нельзя. |
| `atlas-geometry.js` | Чистые операции с координатами GeoJSON для выбора пересечением и включением | Не зависит от DOM, состояния приложения или Leaflet. В Node доступен через `require`. |
| `app.js` | Состояние, загрузка манифеста и слоёв, показатели, фильтры, панели и экспорт | Большой исторически наращённый файл с обёртками; одноимённые функции встречаются повторно. Изменения требуют проверки фактически действующего обработчика. |
| `selection-sketch.js` | Видимый SVG-контур рамки и полигона поверх карты | Данные выборки не вычисляет. |
| `timeline-axis.js` | Непрерывная ось временной шкалы при прокрутке | Пересчитывает длину после изменения списка годов и ширины окна. |
| `map-runtime.js` | События карты, выбор по клику, видимость и порядок слоёв, подписи, карточка наведения | Устанавливает обёртки над функциями `app.js` и ждёт создания `state.map`. Внутренние идентификаторы `V149` остаются для CSS и сохранённых настроек. |
| `data/manifest.json` | Годы, пути к слоям, границы и сведения о сборке | Путь должен существовать; отсутствие слоя в некоторые годы допустимо только там, где код обрабатывает отсутствие. |
| `data/` | Подготовленные временные срезы и результаты аналитики | Исходный материал, не «мусор» от старой версии интерфейса. |
| `scripts/atlas_healthcheck.py`, `scripts/validate_admin_geojson.py`, `tests/` | Проверки путей и схемы административного слоя, тесты инструментов | Не заменяют проверку интерфейса в браузере. |
| `pipeline/recalc_v*.py`, `pipeline/scripts_topology_v94.py`, `pipeline/scripts_topology_v119.py`, `pipeline/build_connectivity_v138.py`, `pipeline/postprocess_connectivity_v138.py` | Расчётные этапы данных Западной Сибири | Номера обозначают методические этапы. Не исполняйте пакетно: скрипты могут перезаписать готовые данные. |

Диагностические `*.csv` в `docs/diagnostics/` и отчёты в `docs/reports/` фиксируют результаты расчётов и происхождение показателей. Их исторические номера не являются версиями фронтенда. Состав и ограничения метрик описаны в [METHODS.md](METHODS.md).

## Поток при работе карты

1. `index.html` подключает Leaflet и html2canvas, затем геометрию, приложение, SVG-эскиз, runtime и модуль временной оси.
2. `app.js` создаёт `state`; его завершающий bootstrap вызывает `init()`, который читает `data/manifest.json`, создаёт Leaflet-карту и загружает первый временной срез. Начальный год сейчас установлен на 1914, если он есть.
3. `refreshAll()` читает гидрографию, административные полигоны, центры и железные дороги; `refreshAdmin()` фильтрует объекты, пересчитывает видимые показатели и создаёт `L.geoJSON`. `state.refreshSeq` защищает от устаревшего результата при быстрой смене года.
4. `map-runtime.js` подключается к созданной карте, управляет порядком и видимостью слоёв, событиями, подписями и выборкой. Клик по АТЕ обновляет `state.selectedIds` и показывает её атрибуты; рамка и полигон показывают эскиз через `selection-sketch.js` и передают координаты в `atlas-geometry.js`. Символы населения находятся в собственной панели Leaflet, показывают карточку при наведении и выбирают исходную АТЕ кликом.
5. Экспорт и специальные аналитические панели читают дополнительные записи манифеста по запросу. Не все функции `app.js` вызываются при первоначальном отображении.

`app.js` и runtime используют глобальные функции/состояние, поэтому они пока не являются независимыми модулями. Часть исторических патчей запускается по `DOMContentLoaded` и через отложенные обработчики. Полный перенос на ESM потребует сначала выделить остальные подсистемы и проверить интерфейс в браузере. Нельзя механически удалить функции только потому, что рядом есть более новая версия.

## Контракт административного слоя

`manifest.layers.admin["2021"]` указывает на GeoJSON `FeatureCollection` с геометриями `Polygon`/`MultiPolygon`. Координаты задаются по стандарту GeoJSON: **[долгота, широта]**, WGS84 (EPSG:4326). В Leaflet тот же объект передаётся как `[широта, долгота]`. Для минимального административного слоя важны:

| Свойство `properties` | Использование |
| --- | --- |
| `unit_id` | Устойчивый идентификатор АТЕ внутри среза, ключ выбора; не должен повторяться в одном году. |
| `year`, `name`, `unit_type` | Подписи, атрибуты и группировки. |
| `admin_parent` | Цвета по АТД-1 и выбор всех видимых дочерних АТЕ одним кликом. |
| `admin_intermediate`, `admin_superparent` | Дополнительные иерархические режимы. |
| `area_km2`, `population`, `density`, `urban_share` | Статистика, фильтры и тематические карты; отсутствие значения требует проверки конкретного режима. |
| `include_in_selection`, `include_in_analytics` | Если значение строго `false`, объект исключается соответственно из выборки или статистики. |

Реальные записи содержат гораздо больше полей: топологию, связность, железные дороги, происхождение границ. Эти режимы используют собственные имена полей и связанный набор JSON/CSV. Для работающей карты с одной темой недостаточно заменить только `data/admin/` при включённых специальных слоях.

Команда `python3 scripts/validate_admin_geojson.py` проверяет все административные срезы: уникальность `unit_id` внутри года, тип геометрии, замкнутость контуров и диапазоны координат. В текущем наборе она обнаруживает пять исторических объектов без `name`, `unit_type`, `admin_parent`, но не считает их технической ошибкой. Отсутствующие исторические названия нельзя автоматически восстановить. Для нового набора запустите её с `--strict-labels`, если эти поля обязательны для всех объектов.

## Если коллеги делают атлас Турции

1. Сначала зафиксируйте минимальный набор временных срезов и административную иерархию (например, провинция/район), включая изменение границ между годами. Подготовьте GeoJSON с уникальными `unit_id`, `name`, `unit_type`, `admin_parent` и координатами WGS84. Не считайте современную иерархию применимой ко всем историческим срезам.
2. Создайте свой `manifest.json` с `years`, `layers.admin` и географическими границами; сохраните отдельную копию сибирских данных. `scripts/atlas_healthcheck.py` проверяет существование всех путей манифеста, включая шаблоны с `{year}`.
3. Перенастройте в `app.js` начальный год `init()`, границы/масштаб карты, списки опорных лет и тематические режимы (`valField`, `adminStyle`), а также русские подписи в `index.html`. Сейчас ряд мест содержит заданные годовые пороги и географические названия Сибири; проверьте их поиском по `1914`, `2021`, `1959`, `Сибир`, `Тобол`, `Зайсан`.
4. Начните с административной карты, затем добавляйте население, транспорт, топологию и связность по отдельности. Схемы аналитических данных и принципы исключения объектов переносите осознанно: методика ВКР описывает конкретные исторические источники и не должна автоматически наследоваться другой территорией.
5. Выполните проверки из README и вручную проверьте два непохожих года, границы с отверстиями, выбор рамкой/полигоном, фильтры, управление слоями и экспорт. Если нужны лишь общие приёмы выбора, можно использовать `atlas-geometry.js` отдельно, без остальных модулей.

При полном переиспользовании UI удобно постепенно выделять загрузчик и нормализацию данных, затем модель состояния/фильтров, тематические слои и экспорт. На каждом этапе проверяйте действующий вызов, поскольку `app.js` всё ещё содержит наследованные переопределения и фиксированные географические допущения.
