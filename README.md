# Исторический веб-атлас Западной Сибири

Интерактивные временные срезы административно-территориального деления Западной Сибири, населения, транспорта и пространственных связей. Проект создан для ВКР и работает как статический сайт: серверная часть и сборка не требуются.

## Запуск

Из корня репозитория запустите локальный HTTP-сервер:

```bash
python3 -m http.server 8000
```

Откройте `http://localhost:8000/`. В Windows вместо `python3` обычно используется `py`. Открытие `index.html` напрямую через `file://` не подходит, поскольку браузер блокирует загрузку GeoJSON через `fetch`. Для оболочки нужны Leaflet и html2canvas из CDN, указанных в `index.html`; картографические данные находятся в `data/`.

## Работа с выборкой

| Инструмент | Действие |
| --- | --- |
| Курсор | Клик по АТЕ показывает её атрибуты и выделяет объект. Перетаскивание двигает карту. |
| Рамка | Протяните прямоугольник по карте. |
| Полигон | Поставьте вершины кликами, завершите двойным кликом, Enter или правой кнопкой. Backspace удаляет последнюю вершину, Escape отменяет контур. |
| Область АТД-1 | Клик по АТЕ выбирает видимые объекты с тем же значением `admin_parent`. |

Для каждого инструмента можно выбрать действие «Новая выборка», «Добавить» или «Убрать». Shift временно добавляет, Alt временно убирает. Для рамки и полигона есть критерии «Пересекает контур» и «Полностью внутри». Пространственная выборка работает по геометрии, а не по центру прямоугольника. Панель справа показывает атрибуты объекта и статистику выборки. Фильтры АТЕ и временной срез ограничивают доступные для выбора объекты.

## Структура

- `index.html`, `style.css`: интерфейс и оформление.
- `app.js`: загрузка временных срезов, расчёт показателей, экспорт, фильтры и пространственные операции.
- `map-runtime-v149.js`: актуальный слой отрисовки, подписей и событий карты; имя сохранено для совместимости.
- `data/manifest.json`: перечень временных срезов и путей к данным.
- `data/`: GeoJSON и аналитические данные. Исходные файлы для атласа, не генерируются при запуске.
- `docs/METHODS.md`: методика показателей, допущения и ограничения интерпретации.
- `docs/CHANGELOG.md`: основные этапы развития проекта и текущие изменения.
- `docs/*.csv`, `data/`: диагностические таблицы и картографические данные.
- `*.py`, `scripts/`: исторические расчётные скрипты. Их запуск может перезаписать данные и манифест старой версией; сначала изучите входы и выходы конкретного скрипта.

Версия в имени `recalc_v*.py` обозначает этап обработки, а не заменяемую версию одного скрипта. Например, расчёты возраста районов и геодезической длины ЖД независимы. Для действующей модели потенциальной связности оставлены `build_connectivity_v138.py` и `postprocess_connectivity_v138.py`: последний формирует метод, указанный в текущих рёбрах `data/connectivity/`. Оба файла перезаписывают результаты и не запускаются при просмотре атласа. Ранние сборщики v129–v137 доступны в истории Git.

## Проверка изменений

```bash
node --check app.js
node --check map-runtime-v149.js
node --test tests/*.test.js
python3 -m json.tool data/manifest.json > /dev/null
python3 scripts/atlas_healthcheck.py
```

Перед публикацией стоит проверить интерактивно на нескольких временных срезах: клик по АТЕ и карточку объекта, рамку и полигон с обоими пространственными критериями, режим области, переключение года, фильтров и слоёв. Существующий `app.js` содержит много накопленных версионных обёрток. Дальнейший рефакторинг нужно делать по подсистемам с визуальной регрессией, сохраняя научную методику расчётов.

## Данные и источники

Основные методические оговорки сведены в [METHODS.md](docs/METHODS.md), а история ключевых изменений в [CHANGELOG.md](docs/CHANGELOG.md). Подробные операции с данными доступны в диагностических CSV/JSON `docs/`, исходных расчётных скриптах и истории Git. Перед повторным использованием набора проверьте применимость конкретного временного среза: реконструкции не образуют однородный ряд современных АТЕ.
